# ポストフロップソルバー設計計画

作成: 2026-09-24 / 設計: Claude / 実装: Codex（分担は末尾）

## 1. 目的

1. **外部サービスに頼らず品質を測れる基準を持つ。** ソルバーの品質はエクスプロイタビリティ（相手が最善の対応をしたときの損失）で自前計算でき、GTO Wizard 等との比較を不要にする。
2. **フロップ以降の戦略を提供する**（初中級者向けにAIが説明する前提のデータ源）。
3. **プリフロップの推定レンジを損得で検証する。** 現在のプリフロップ損得モデル（`scripts/open-ev.mjs`）は「ポストフロップでどれだけ勝率を回収できるか」を固定値で仮定しており不正確。ここをソルバーの計算値に置き換える。

### 成功基準
| 項目 | 目標 |
|---|---|
| 正しさ | 解析解が既知の小さなゲームで一致（誤差 < 0.1%）。対称性・決定性テストが通る |
| 品質 | 配信するスポットはエクスプロイタビリティ ≤ 0.5% pot（看板スポットは ≤ 0.3%） |
| 速度 | シングルレイズポット（SRP）のフロップ1スポット、サイズ2種類で、Apple M系8コアで ≤ 60秒 |
| メモリ | 同条件で ≤ 2GB（f16 圧縮オプションで ≤ 1GB） |

## 2. 方針（現行プリフロップソルバーとの違い）

| | 現行（preflop） | 新規（postflop） |
|---|---|---|
| 探索 | 外部サンプリング（プライベートコンボを抽出） | **ベクトル形式の全列挙**（レンジ対レンジ、全コンボを同時に更新） |
| 更新則 | DCFR | DCFR（α=1.5, β=0, γ=2）。必要なら DCFR+ / 線形CFR を比較 |
| エクスプロイタビリティ | サンプルによる推定 | **全ツリーのベストレスポンスで厳密計算** |
| 終端評価 | 強さの代用値 | 7枚評価器＋カード除去付きの O(n log n) ショーダウン計算 |

外部サンプリングは結果がぶれやすく、エクスプロイタビリティの厳密計算とも相性が悪いため、ポストフロップは全列挙にする。

## 3. 段階（フェーズ）

### P0 基盤（1〜2週）
- **7枚ハンド評価器**（`crates/hand-eval`）: ルックアップテーブル方式。1秒あたり数億評価を目標。全 C(52,7) の役分布を既知の値と照合するテスト。
- **レンジとボードの表現**: ボードと重ならない 1326 → 最大1081コンボ、カード除去用のブロッカー表。
- **スート同型**（isomorphism）: ボードのスート対称性でコンボとチャンスカードを縮約（フロップによって最大 ~4倍の削減）。

### P1 リバー単独ソルバー（1〜2週）
- 公開情報（ボード5枚・ポット・スタック・両者のレンジ）から、リバーのベット／レイズツリーを解く。
- 正しさの基準: 解析解が既知のトイゲーム（例: クレアボヤンス・ゲーム、ポーラー対コンデンスのリバー）で理論値に一致。
- 厳密エクスプロイタビリティ（全ツリーのベストレスポンス）を実装し、反復とともに単調に下がることを確認。

### P2 ターン＋リバー（1〜2週）
- チャンスノード（リバーの46〜48枚）を全列挙。スート同型で縮約。
- 並列化（rayon）: チャンスの分岐ごとに並列。

### P3 フロップ→リバー（2〜3週）
- 最初の対象スポット:
  1. BTN オープン vs BB コール（SRP、ポット 5.5BB、残り 97.5BB）
  2. CO オープン vs BTN コール（SRP、IP同士ではない形の確認用）
  3. BTN オープン vs BB 3bet 12BB → コール（3betポット）
- 開始レンジはプリフロップの保存データから作る（コール／3bet の頻度で重み付け）。
- メモリ見積り: 後述 §6。

### P4 プリフロップとの接続（2週）
- `crates/continuation` の `ContinuationEvaluator` を、**代表フロップの集合**で解いた値に置き換える。
  - 代表フロップ: スート同型で 1,755 種類 → 重み付きの縮約集合（例: 49 / 95 / 184 種類）から開始し、集合サイズによる結果の差を計測して選ぶ。
- 得られたポストフロップEVで `open-ev` の実現率仮定を置き換え、プリフロップ推定レンジを損得で再検証する（監査の新しいチェックとして追加）。

### P5 ライブラリと配信（継続）
- よく出るスポット×代表フロップを事前計算し、`solutions/` → 検証 → R2 公開の既存経路で配信。
- UI: フロップの戦略表示と、AIによる解説（「ソルバーで検証済み」の表示）。

## 4. ゲームの抽象化（設定ファイル化）

`configs/postflop/<name>.json` に置き、ソルバーはこれだけを読む。初期値:

| ストリート | ベット（ポット比） | レイズ | その他 |
|---|---|---|---|
| フロップ | 33%, 75% | 3倍 | ドンク（OOPの先打ち）なし |
| ターン | 50%, 100% | 3倍 | ドンクなし |
| リバー | 50%, 100% | 3倍 | オールイン常に可 |

- 残りスタックがポットの一定割合以下（例: 150%）になったらオールインに丸める。
- レイズは1ストリートあたり最大2回（キャップ）。
- サイズは後から増やせるが、ツリーとメモリが増えるため、増やす前に §6 の見積りを更新する。

## 5. データ形式

- ノードID: プリフロップと同じく**アクション履歴の正規キー**（例: `F:X|B33|C;T:X|X;R:B100`）から決定的に生成。
- 戦略: ノードごとに `[コンボ × アクション]` の頻度。保存は uint8（0〜255 → 0〜100%）で量子化、スート同型で縮約した形のまま保存し、表示時に展開。
- メタデータ: 抽象化設定のハッシュ、開始レンジのハッシュ、反復回数、エクスプロイタビリティ（% pot）、ソルバーのバージョン。
- 既存の `crates/solution` の Repository 抽象に乗せ、プリフロップと同じ公開フロー（Promote / 検証 / R2）を使う。

## 6. 規模の見積り（P3 の SRP、サイズ2種類）

- アクションノード: フロップ ~30、ターン ~30×47、リバー ~30×47×46 → **概算 7万〜10万**（チャンス縮約前）。
- 1ノードあたり: 1081コンボ × 平均3アクション × (後悔値＋平均戦略) × 4byte ≈ 26KB。
- 合計 ≈ 2〜2.6GB（f32）→ スート同型と f16 圧縮で ≈ 0.6〜1GB。目標の ≤2GB に収まる見込み。サイズを3種類に増やすと約2倍になるため、段階的に。

## 7. 品質保証

1. **解析解テスト**（P1）: 既知のトイゲームで理論値に一致。
2. **エクスプロイタビリティ**: 反復ごとに記録、配信の合否基準（≤0.5% pot）。
3. **不変条件テスト**: 各ノードの頻度合計 = 1、到達確率ゼロのコンボの扱い、スート同型で展開した結果と非縮約で解いた結果の一致（小さなツリーで）。
4. **決定性**: 同じ入力・同じスレッド数で同じ出力。
5. **回帰ベンチマーク**: 速度とメモリを CI で記録し、劣化を検知。

## 8. ライセンスと独自性

- オープンソースのポストフロップソルバーには AGPL など商用利用に条件が付くものが多い。**コードは参照・流用しない**（公開論文のアルゴリズムから独自実装）。依存ライブラリは MIT / Apache-2.0 のみ。
- 外部サービスの戦略データは、較正・比較にも使わない（エクスプロイタビリティで自前評価する）。

## 9. 構成（新規 crate）

```text
crates/hand-eval        7枚評価器・同型・ブロッカー表          （P0）
crates/postflop-tree    抽象化設定からのツリー生成・ノードID   （P1〜P3）
crates/postflop-solver  ベクトル形式DCFR・厳密BR・並列化       （P1〜P3）
services/postflop-worker 既存 job-queue で動くワーカー        （P3〜）
configs/postflop/*.json  抽象化設定
```

`crates/continuation` は P4 で `PostflopContinuation`（代表フロップの解から評価）を追加する。

## 11. リスク

| リスク | 対策 |
|---|---|
| メモリ・計算時間が見積りを超える | サイズを絞って開始、f16、同型縮約、スポットの事前計算に限定 |
| 抽象化（ベットサイズ）の粗さで戦略が不自然 | サイズ追加による差をエクスプロイタビリティとEVで計測してから増やす |
| 3人以上のポット | 初期は対象外（2人のみ）。プリフロップ側のマルチウェイは推定データのまま |
| 評価器・ツリーのバグで「収束しているが間違い」 | 解析解テストと、同型あり／なしの一致テストを P1 から必須に |

## 12. 最初のマイルストーン（P0＋P1）

1. `crates/hand-eval`: 7枚評価器、全列挙の役分布テスト、性能ベンチ。
2. `crates/postflop-tree`: リバーのみのツリー（ベット 50/100%、レイズ3倍、オールイン）。
3. `crates/postflop-solver`: ベクトル形式DCFR、厳密ベストレスポンス、エクスプロイタビリティの記録。
4. 解析解テスト（クレアボヤンス・ゲーム）と、実レンジでのリバー1スポットのデモ（CLI）。
5. 合格基準: 解析解と一致、エクスプロイタビリティが 0.1% pot 以下まで下がる、1スポット ≤ 5秒。
