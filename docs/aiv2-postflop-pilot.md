# AIv2 exact-decision postflop pilot

## Current bounded scope

Only `BTN_open_BB_call`, 100BB initial stacks, BTN open 2.5BB, BB call,
flop `As7d2c`, BB check, BTN to act. Pot 5.5BB; each live stack 97.5BB.
The BB check is an explicit probability-one initial-line assumption, not a
model-generated BB checking range. Profiles and other spots/runouts/branches
are not generated by this pilot. Generic transition helpers do not imply
coverage of any turn/river decision.

Legal first actions: check, bet33, bet66, bet100, bet125. Their paid amounts
are 0, 1.82, 3.63, 5.50 and 6.88BB. Never substitute legacy bet75.
The isolated helper uses effective-stack caps, 3x raise-to with a legal
minimum increment, maximum four raises, reopening checks and the existing
67%-of-effective-stack all-in merge. Raise-to amounts are not pot percentages.

## Authoring

`node apps/frontend/scripts/aiv2-postflop-cli.ts --status` is read-only/dry by
default; `--prompt` also prints the exact prompt/schema, without inference.
Only the coordinating human-authorized runner may use
`--generate --confirm-one-decision-quota`. Normal execution makes one call
using authenticated local Codex, gpt-6.1-sol/medium. At most one correction
is allowed for invalid JSON/response validation, in the same scene lease;
transport/model/auth/quota failures are not replayed. Each turn has a
600-second provider deadline. There is no multi-board/scene loop.

Base v6 source policies are decoded from exact class defaults plus physical
combo overrides, never reconstructed from weighted display rows. Only each
player's own prior actions condition that player's range. Board blockers
are removed. Zero-own-reach combos are not requested or included in weighted
aggregates. The first frozen input has 646 positive BTN and 827 positive BB
physical combos; these are not independently card-removal-conditioned joint
deals.

## Saved artifact / UI handoff

Files: `apps/frontend/candidates/aiv2-postflop/llm-postflop-single-response-v1/decisions/<decision_id>.json`.
No source generation occurs while loading a saved file.

- `kind: aiv2_saved_postflop_decision`
- `schema_version: aiv2-postflop-decision-v1`
- `input`: exact board/street/actor, chips, public postflop history, preflop
  history, both complete 1326-combo weight maps, upstream policy/content hashes
  and assumptions.
- `legal_actions`: `{action, paid_bb, to_bb, all_in}`.
- `source_response`: original single compact model JSON containing
  `decision_id`, `range_summary:{text,text_ja}` and explicit
  `groups:[{combos,mix,text,text_ja}]`.
- `summary`: exact saved `range_summary`.
- `combos`: program-expanded `{combo,hand,reach_weight,mix,text,text_ja}` for
  every positive actor combo exactly once. Groups explicitly enumerate exact
  physical cards sharing a mix AND rationale; they never imply a hand-tier or
  suit-symmetry frequency rule. Physical exceptions remain independent.
- `hands`: all canonical169 rows with board-legal `combo_count`,
  `reached_combo_count`, `reach_weight`, `unreachable` and reach-weighted
  `frequencies` in percentage units. Unreachable rows have empty frequencies.
- `metadata`: method/version/model/effort, implementation/input/response/policy
  hashes and `coverage: one-exact-board-public-history-actor-only`.

Canonical combos use ranks `AKQJT98765432`, suits `shdc`, deck pairs i<j.
All internal hashes are SHA256(JSON.stringify(value)) with existing key order,
not key-sorted JSON. `input_hash` binds input; `response_hash` binds the whole
source response; `policy_hash` binds expanded combos including reasons.
`decision_id` binds method/version/model/effort/implementation/input/legal
options. A publication manifest must separately bind raw file bytes and allow
only saved board/history/actor identities. Saved artifact validation rebuilds
and compares the complete artifact. Existing cache identities are exclusive
creation and never silently overwritten/relabelled.

`advancePostflopDecision(saved,action,nextCard?)` validates the saved artifact,
conditions only that actor's own physical reach, and returns a next decision,
a terminal state, or `next-street-card-required`. It does not invent a next
card, implicit check, action range, or missing policy. Subsequent inputs must
be prepared from saved predecessors and explicitly selected runouts; the CLI
`--input=<prepared-json>` does not itself generate predecessor coverage.

EN/JA presence, exact coverage and numeric/legal consistency are checked in
code. Natural-language strategic correctness and translation fidelity still
need independent review; passing numeric validation is not solver/GTO proof.
