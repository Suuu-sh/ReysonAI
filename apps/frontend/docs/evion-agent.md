# Evion Agent（HU）設計

作成: 2026-10-03。AI推定の対戦相手機能。GTO・均衡解・利益の証明ではありません。

## 目的

Evion solver（保存済みのAI推定方針）通りに打つAIと、ヘッズアップでリバーまで対戦できる卓を作る。
Agent はプレイヤーの分析結果を読み、相手像別レンジ表が揃った局面ではプレイヤーに合わせた方針へ切り替えてエクスプロイトする。

## 段階

| 段階 | 内容 | 前提 |
| --- | --- | --- |
| A1 卓エンジン | 1ハンドの進行（配札・プリフロップ・フロップ〜リバー・ショーダウン・精算）を純関数で | 既存の保存レンジとポストフロップ方針 |
| A2 均衡Agent | Agent は自分の実カードの頻度で行動を抽選。方針が無い経路は配らない | A1 |
| A3 卓UI | 既存トレーナーの卓見た目を流用。ハンド履歴・スタック推移 | A2 |
| A4 プレイヤー読み | 分析（`player-analysis.ts`）＋卓内の実績から「読み」を作る | A3 |
| A5 エクスプロイト | 読みに一番近い相手像の方針へ切り替え。表が無い局面は均衡のまま | 相手像別レンジ表 |
| A6 種明かし | ハンド後に「Agentが突いたあなたの傾向」を表示 | A5 |

全てのレンジ表が揃うまで A5 は部分的にしか効かない。A1〜A4 とプラグイン口（下記）を先に作り、表が増えるたびに効く局面が増える形にする。

## 対応範囲（A1〜A2）

- 形式: 6-max キャッシュ 100BB の席名で、実際に参加するのは2人（他席は即フォールド扱い）。
- 経路: ポストフロップAI推定の到達可能44経路のうち、**保存済みのフロップ方針とターン・リバー方針が両方そろっている経路だけ**。毎ハンド、その中から経路を選び、プレイヤーと Agent の席を割り当てる。
- プリフロップ: 保存レンジ（RFI・対オープン・3bet/4bet応答・SBリンプ系）の該当手の頻度。経路から外れる行動（例: 経路に無い5bet）が選ばれたら、そのハンドはそこで決着（フォールド・オールインのみ扱える範囲）。プリフロップで2人とも残り、対応経路に入ったらポストフロップへ。
- ポストフロップ: `computeBoard` / `computeLaterView` と同じ計算（`views.mjs` の per-combo mix）。Agent は自分の実コンボの mix から抽選。
- 未対応の経路・方針欠損・ハッシュ不一致のときは、別局面の方針で代用せず、その経路を出題候補から外す。

## Agent の判断の層

```
decide(state, agentCards) =
  base   = 均衡方針の mix（保存データ）
  read   = プレイヤー読み（A4）
  policy = profilePolicy(spot, node, read) ?? base   // A5：相手像別の表があれば差し替え
  sample(policy[agentCards])
```

- `profilePolicy` はプラグイン口。相手像別データセットの登録表（局面 × 相手像 → 方針）を引くだけで、実行時にLLMは呼ばない。
- 相手像の選択は読みの指標（fold/3bet のずれ、局面別のずれ）から決定的に行い、サンプル数が閾値未満なら均衡のまま。閾値はプレー分析の既存基準（30問など）に合わせる。
- 相手像別の表自体が「AIが決めた打ち方」なので、Agent側で頻度を独自に作り変えない（保存頻度以外を発明しない、既存ルールと同じ）。

## 決定性・テスト

- 乱数はシード付き（ハンドIDから導出）。同じシード・同じプレイヤー行動なら同じハンドになる。
- A1 のテスト: 精算の総額保存、サイドポット不要（HU）、オールイン後の自動進行、ショーダウン勝敗、方針欠損経路の除外。
- A2 のテスト: 大量シミュレーションで Agent の実行頻度が保存 mix と一致（許容誤差内）。

## まだ決めていないこと

- 卓のチップ単位・リバイ・セッションの長さ。
- Agent の名前・見た目（複数キャラにするか）。
- 対戦結果をランク戦やプレー分析に入れるか（当面は入れない想定）。
