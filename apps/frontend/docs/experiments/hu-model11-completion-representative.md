Research-only, explicit opt-in, based on frozen `85a44ec419b9d449c4715bab3ad7f328b54499fd` (tree `30a3ae93494cb1e391f4ec604109c04af17a2322`). Every preexisting tracked byte is preserved. This additive report is not the original strict-law simulation v2 and cannot satisfy that validator. Default/model10, old45, accepted policies, typed/Range/Agent/admission, all1755 strict-board gates and deterministic strict zero-proof classification are unchanged.

## Binding and exact work

The new binding explicitly pairs the original immutable strict-balance execution with the separately versioned composite behavior execution and saved completion-policy identity. Belief, raw12 sources and artifact provenance remain strict. The existing `resolveModel11GatePlan` supplies the ordered official12 boards × standard/passive/aggressive × IP/OOP ×10000 samples (720000 total), street `all`, inherited seed/config and the saved full plan with cache batch512. The original diagnostic cap12 stays unchanged. Internal fixed96 parity is separate from the public gate plan.

The new narrow cell runner reuses `playModel11Hand`, original `playHand` baseline, original deal/runout/24-random stream and `summarizeModel11Trials`. Each cell starts at its identical original seed; cache release occurs at index0 and every512, without extra RNG calls. All completed paired returns, including completed-by-policy returns, enter the unchanged ordered floating-point mean/variance computation. Any unresolved trial nulls the cell's entire paired EV. Invalid/unproven certificates, illegal actor support, underflow and other invalid execution remain hard errors, never substituted EVs.

## Fixed receipts and bounded retention

Each trial is recorded once with its contiguous cell index and paired returns. Completion events retain request, actor own combo, random index/value, sampled label/physical action, full declared law/hash, original off-model status, semantic verification and separate identities. Certificates are immutable proofHash-named files; saved laws reference that hash and are rehydrated before their original lawHash is checked. The actor's own combo is evidence outside the policy; opponent cards, future runout and profile never enter the completion adapter.

The existing immutable writer/path guards save trial chunks at512 cache boundaries, or earlier when encoded trial bodies reach8MiB. Evidence partitioning does not reset or reseed execution. At most one chunk and one cell's10000 paired-return arrays are retained, rather than720000 trial objects or repeated whole certificates. Each completed cell marker is written only after exact index/count/hash, metrics and semantic event/proof validation. Interrupted chunks cannot act as completion markers. Report restart accepts only fully validated same-binding markers and safely recomputes incomplete cells. Resume validates evidence; it is not an attestation that all original deals were freshly executed. Only the separate fresh audit supplies that numerical replay. Audit requires every original saved marker and an independently empty replay evidence directory; it cannot resume the fresh replay.

The source CLI captures the new reviewed closed graph and the unchanged strict graph/raw12, source fingerprint, artifact and plan bytes before/after. Cell records have exact order and content/file hashes. Every persisted completion event calls `complete(request, ownCombo, proof)`, which rebinds actor support/current ancestor and replays all support rows; a rehashed incomplete certificate cannot pass. No semantic memo bypass exists in this implementation.

Peak heap/RSS and run duration at full scope are unmeasured. The earlier96 source/runtime evidence is a correctness prerequisite, not a scale benchmark or numerical-quality pass. Pair arrays are small; actual law/cache memory, proof diversity and disk size still require authorized independent measurement. No full-pass claim is made before full report + fresh audit finish.

## Audit and unchanged quality gates

The separate audit validates every saved file/event/row and then recomputes baseline and candidate from fresh factories/RNG streams, comparing all per-cell returns, event/law/proof evidence, counts and numerical hashes. The original whole12-board strict balance aggregate is computed and validated unchanged, then losslessly saved as an immutable header, bounded prefix parts and proofHash certificate files. Rehydration must recover the exact whole balanceHash and all coverage/results/findings before a compact final receipt can be written. The existing16MiB writer cap is never raised; full prefix evidence is not inlined into the final receipt. It then calls the unchanged expanded legality checker, original strict balance checker/validator, reference-vs-reference zero-drift sanity and original balance error thresholds/warnings. Complete full results remain `unapproved`, and matching strict all-board evidence plus independent review are still required. The failed original95/96 strict report is never overwritten or relabeled.
