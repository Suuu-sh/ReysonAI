# 仕様：マルチウェイ・ポストフロップ 段階1（3人ポット、Astra 向け）

この依頼文そのものがユーザーとメインの Claude からの指示です。確認のために止まらず、最後まで作業してください。
作業は `development` から切った専用ブランチで行い、コミット・push して、`development` 向けのプルリクエストを作るところまで行うこと（下書き PR にする。マージ・本番デプロイ・本番 D1 への取り込みはしない）。他の人の変更は巻き戻さない。

リポジトリ: `Suuu-sh/ReysonAI`（作業はフロントエンドの `apps/frontend` が中心）。

## 0. 背景と最初に読むもの

- ポストフロップは今、2人のポットだけに対応している（`scripts/postflop-ai/` の engine / tree / later-tree / defence / balance と、画面の `src/estimated/postflop-*.ts`、Agent戦の `src/agent/hand.ts`）。3人以上でフロップに行く流れは、レンジ画面では「未収録」、Agent戦では3人目になるコールを出さない（`no_multiway`）扱い。
- プリフロップのマルチウェイのレンジは揃っている（`multiway-responses.json`・`multiway2-responses.json`・`squeeze-responses.json` など）。
- 必ず読む：`AGENTS.md`、`src/estimated/AGENTS.md`、`docs/postflop-policy-knowledge.md`、`docs/postflop-defence.md`、`docs/postflop-ai-pilot.md`、`docs/specs/opponent-profiles-plan.md`（「方針の頻度をそのまま使うモード」の考え方）。

## 1. 範囲（この段階）

- **3人ポットのシングルレイズドポット**だけ：オープン → 1人目がコール → 2人目（後ろの席またはブラインド）がコール → 残りは降りる、でフロップに行く流れ（`multiway-responses.json` のコールで到達するもの）。
- スクイーズや 3bet の後の3人ポット、4人以上のポットは次の段階。
- ヘッズアップの既存の仕組み・方針・照合値・画面は一切変えない（2人ポットの挙動は今と同じ）。

## 2. 決まっている設計（変えない）

1. **人数を一般化した卓**：`engine.mjs` の `createTable` などを、2人専用から「N人（この段階は3人）」に一般化する。ポストフロップの行動順は SB → BB → UTG → HJ → CO → BTN のうち残っている人の順。2人の場合の結果は今とバイト単位で同じにする（既存テストと保存済みの監査レポートで確認）。
2. **ツリー**：3人の各ストリートで、最初の人はチェックかベット（33/75/125%、低SPRならオールイン）。ベットを受けた人はフォールド / コール / レイズ（3倍、1ストリートのレイズは最大2回まで）。ノード名は `mw3_<street>_<seat role>_<situation>` のように、席の役割（first / middle / last）と状況が分かる名前にする。
3. **方針**：ヘッズアップと同じ「手の強さ × ボード（形・高さ）× 流れ」のルール表を、3人ポット用に持つ（`.local/postflop-ai/mw3/<slug>-policy.json` / `-later-policy.json`）。
   - **受け側も含めて、方針の頻度をそのまま使う**（相手像モードと同じ考え方）。2人ポットの計算防御（`defence.mjs`）は使わない。マルチウェイで計算防御を作るのは後の段階。
   - 指示文には、3人ポットの基本を入れる。ブラフは2人ポットより少なく。後ろにまだ人がいる席は、ドローやミドルペアでのコールを控える。ポットを取りに行くのは強い手中心。最初の人はチェックが多い。
4. **破綻チェック**：`balance.mjs` に3人ポット用のチェックを足す。止める（error）のは、合法でないアクション・頻度の合計・到達できない分岐だけ。
   - 警告：3人全員の続行を合わせても、MDF（ベット額に対して最低限守るべき割合）を大きく下回る／上回る。モンスターがほぼフォールドする。役なしのベット・レイズが多すぎる。
5. **画面**：レンジ画面（`PostflopTrial.tsx` / `postflop-trial.ts`）で、3人のレンジ表を並べ、3人の行動ブロックを順に出す。ハンドの説明は、2人用の文面を流用せず「3人ポットでは〜」の簡潔な理由にする（既存の `postflop-explanation-lessons.md` の決まりを守る）。
6. **Agent戦**：3人でフロップに行くコールを出せるようにし、フロップ以降を3人で打つ。

## 3. 作るもの

- 一般化した engine / tree / later-tree と、3人ポット用の局面定義（`spots.mjs` に `kind: "mw3_srp"` など）。対象の流れはプリフロップのデータから列挙し、到達頻度の高い順に作る。
- 3人ポット用の方針の生成（`cli.mjs generate --spot <id> --model gpt-6-astra` を拡張）。
- 3人ポット用の監査・シミュレーション・全ボード点検（`audit-all-boards.mjs` を3人に対応）。
- 画面とAgent戦のつなぎ込み。
- 本番配信の対象に追加（`publish-d1 --only postflop`）。本番への反映は実行しない。
