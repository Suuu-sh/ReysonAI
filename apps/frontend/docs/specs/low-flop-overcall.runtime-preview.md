# Frozen-runtime experimental integration

Status: closed-driver v3 passed the mandatory 36-contract gate with zero skips and independent review accepted its limited research execution. V1/v2 results and their discovered boundary gaps remain separately recorded. The user-facing quality fix remains incomplete; current-model integration, non-preview use, production and remote LFS delivery remain unapproved.

The Node-only `experimental-flop-veto-runtime.mjs` v3 driver is not imported by the application. It privately loads the restored, hash-verified main `2064a41` legacy model-6 runtime. Normal mode uses the original mix. Only the explicit `enableUnapprovedPreview: true` experiment can pass the four original negative exact contexts through the existing preview gate. It creates no review receipt and always reports `production_eligible: false` and `approval: none`.

`experimental-flop-veto-pins.json` binds the original four raw reports, fixed seven-case protocol, replayed context hashes, saved-input bytes, Gate/Builder identities and independent research-review records. The eight additional outcomes are intentionally excluded. The nominal statistical family remains the original seven cases with budget .01. No additional cases or suit-isomorphic expansion are authorized by the adapter.

The original legacy mix is computed first. For an exact board/hand/node/history match, the driver checks the entire pending table's data against the independently replayed state, including spot, chip stacks, investments, pot, winner, previous aggressor, decision log and street histories. Base/raw/final mixes and current snapshot, policy, evidence, protocol and driver-source identities must still match. Any failed or incomplete comparison returns the original mix. There is no floor/ceiling recalculation or refill into other combinations. The underlying Defence object and saved policies are not patched; the driver owns a private instance and freezes its inputs and policy objects.

Unlike v1, no Defence, strategy, engine or table reference escapes. `evaluate` accepts only board/hero/history data and builds its own pending table. `playFixedDeal` accepts only fixed cards, history, a seed and a root quantile, selects the initial action using that private decision, and executes all continuation through the pinned `playFromNode`. Caller-provided engines, drivers, callbacks, tables, hashes or strategies are rejected. A returned single-deal net is an individual outcome, not an expected value. The guarantee concerns execution inside this closed research driver; it cannot prevent someone copying output numbers into unrelated code.

An incompatible fixture or base source produces `ready: false` and no runtime. A consumer must retain its ordinary runtime; it must not substitute a reference strategy or relabel old data as current. The current development branch contains unrelated HU defence changes and does not have the frozen source identity. Old evidence cannot be carried to it by merely changing hashes. Fresh-main use needs new evidence or an independently reviewed equivalence/revalidation decision.

The experimental identity includes base model 6, intervention version 1, experimental adapter version, complete adapter dependency graph and evidence-pins hash. This makes an experimental output distinct from a legacy model-6 artifact. The adapter is not a production API, authenticity verifier, deployment mechanism or source of approved certificates.

## V3 input-boundary correction

Options must have only declared own data properties; symbol keys, accessors and Proxy objects are rejected. History must be a dense, plain array of own string data properties, with no iterator, getter, extra method or sparse position. The entry point reads those descriptors once, constructs a normal frozen array by index and passes that same private copy to root replay, seed encoding and full continuation. Neither a spread nor a second read of the caller’s history participates in the decision. A ninth regression covers custom iterators, getters, proxies, sparse arrays and extra methods without invoking any caller callback. The gate now requires 36 total contracts and records the new source identity. All 36 passed, with unchanged parity/replays and four changed rows among 21,546. Independent execution acceptance is recorded in `low-flop-overcall.runtime-review-v3-execution.md`; exact logs and source identities are in `low-flop-overcall.runtime-validation-v3.json`.
