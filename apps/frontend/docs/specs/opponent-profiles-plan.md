# 相手像モード（HU）全体計画

2026-10-04 ユーザー決定。マルチウェイ段階2より先に行う。

## 決まっていること

- 対象：ヘッズアップのプリフロップ＋ポストフロップ（フロップ〜リバー）。
- 相手像は4つ。
  | ID | 名前 | 相手の打ち方 |
  |---|---|---|
  | `nit` | タイト・パッシブ（NIT） | 参加が狭い。強い手でしか大きく打たない。ブラフが少ない。 |
  | `station` | コーリングステーション | 広くコールして降りない。ブラフ・レイズが少ない。 |
  | `lag` | ルース・アグレッシブ（LAG） | 広く参加し、レイズ・3bet・ブラフが多い。 |
  | `maniac` | マニアック | 非常に広く、過剰にレイズ・オールイン・ブラフする。 |
- 既定は今の「均衡型（標準）」。相手像は追加の選択肢。
- 自分の打ち方（対策）は **AI が判断し、その頻度をそのまま出す**。EV 最大化で決めない。計算は「事前の破綻チェック」と「計算上は○○の方がEVが高い」という補足表示だけに使う。
- 1つの相手像は「相手の戦略」と「自分の対策」の組。相手側の席はその相手像の戦略、自分側の席は対策で表示する。

## 段階

| 段階 | 内容 | 担当 |
|---|---|---|
| A | プリフロップの相手像データ（4相手像 × HU 全データセット：相手の戦略＋自分の対策＋理由文） | Astra（仕様書: `opponent-profiles-stageA-preflop.md`） |
| B | 画面：相手像の選択、データの読み込み、表示の切り替え、理由文。今の「卓の傾向（コール/3bet 頻度の多い/少ない）」は相手像に置き換える | Claude が仕様、実装は Astra または Claude |
| C | ポストフロップの相手像モードの仕組み：相手像ごとの方針ファイル、両者とも方針の頻度をそのまま使う（計算防御を使わない）、破綻チェックと EV 補足 | Claude が設計、実装は Astra |
| D | ポストフロップの方針生成：4相手像 × 44局面（相手の方針と自分の対策）、全ボード点検 | Astra |

## データの持ち方（案）

- プリフロップ：`src/estimated/profiles/<profile>/<dataset>.json`（既存と同じ形式）＋ `src/estimated/profiles/<profile>/reasons/<spot>.json`。
- ポストフロップ：`.local/postflop-ai/profiles/<profile>/<slug>-policy.json` / `-later-policy.json`。
- 利用時に LLM は呼ばない（事前生成のみ）。
