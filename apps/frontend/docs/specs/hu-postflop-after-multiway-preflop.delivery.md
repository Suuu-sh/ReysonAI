Version 1. Prepared 2026-10-04 UTC by the implementation author (OpenAI assistant). The requested policy-authoring model is gpt-6-astra with xhigh reasoning. The implementation model identifier is not exposed by this execution environment; it is not invented here. Independent review is a separate role/model recorded in a separately supplied dated receipt. This stable contract describes conversion and validation; it is not a batch approval, numerical proof, production instruction, or per-batch journal.

## Compatibility boundary

The original v1 archives, manifest/receipt gates, numerical entry points, serial-validation graph, policy/report bytes, contractual documents, knowledge files and package manifests remain unchanged. The collection adds downstream entry points only. No existing numerical or v1 module imports them. Graph/byte comparisons must establish that boundary for the exact implementation commit. Historical accepted bytes remain historical and fail against a changed current source baseline.

A collection's complete transitive delivery source ledger includes every added entry, bounded worker, test, this document, verification workflow, dummy local config, original reused verifier/serializer dependencies and every backend migration consumed by the oracle. Changing any bound file requires a new collection index, deterministic conversion and independent collection/delivery review. It does not authorize rewriting original numerical proofs.

## Exact collection format

Schema version 1, kind `postflop-reviewed-shard-index`, approval `unapproved`. Canonical JSON uses the existing `jsonBytes` convention. `content_sha256` hashes the complete index excluding only that field. The separate receipt also binds the final raw index byte hash.

The actual catalog is exactly 407 current new IDs, A137/B270, with its catalog-file byte record and the sorted-ID hash. Acceptance is the nonempty, sorted, disjoint union of separately accepted child IDs. Coverage explicitly lists every remaining catalog ID with a nonblank reason. Complete-catalog means all actual IDs, never just all selected shards.

Each child is an unchanged v1 manifest/archive/independent receipt with exact raw path/length/SHA-256 records. All child sources/input arrays and aggregate hashes must match one common executing baseline. Every included spot must be new, accepted by that child's receipt, and contain its own fresh authored flop/later pair, report, representative replay proof, and complete original 1,755-board all-street companion/evidence. The unchanged `readSnapshot` and `assertIndependentReview` enforce those gates. No legacy spot, unaccepted extra candidate, duplicate ID/slug/destination/record/receipt/path, precedence rule or filesystem-discovered freshness selection is allowed.

Bounds checked before whole-shard decoding: at most 8 spots, 128 artifact records, 16 MiB per original file, 32 MiB total expanded artifact bytes and 8 MiB compressed per child. Index <=4 MiB; child manifest/receipt <=8 MiB; <=407 shards/accepted IDs, <=4,096 destinations, <=2 GiB declared aggregate artifact disk use. Staging/restoration require a positive free-space preflight. Oversized data fails; bounds are not silently raised.

One fresh worker runs at a time. It has a 768 MiB V8 heap cap and a separately measured 1.5 GiB RSS ceiling. Parents retain metadata ledgers, not all decoded shards. Worker max RSS is returned per shard. The local importer has a 3 GiB measured command-RSS ceiling. Heap/RSS values are different limits; neither is a simultaneous process-tree aggregate guarantee.

## Review and deterministic conversion

A separate independent delivery receipt binds raw index/content/source identities, all ordered child identities, actual accepted union/catalog/deferrals, fixed ISO publication time, unique immutable revision, exact predecessor content hash or explicit null, complete SQL hash/length and the compact D1 row-value ledger hash. Author/reviewer identities, review time, baseline commit, scope and zero blocking findings are required. Packaging never writes that receipt; strings alone do not constitute substantive independent examination.

The explicit local package builder accepts named reviewed children, explicit deferrals and publication parameters. It produces intrinsically unapproved collection metadata and optional unapproved candidate SQL under ignored local paths. No numerical generation, audit, policy regeneration or receipt creation is performed.

Formal preparation revalidates each child in a serial first pass, then revalidates/serializes one bounded shard in each fresh process. Policy/report values come directly from decoded snapshot bytes, regardless of different ambient canonical files. Original `buildSql` is called for each accepted spot with explicit fixed time/revision. Its exact scoped row semantics and compact JSON strings are preserved. Its per-spot dataset footers remain; one authoritative collection footer follows in the same complete file.

Every complete escaped statement, including combined metadata/policy strings, doubled apostrophes and SQL wrapper, must be <=90,000 UTF-8 bytes. All policy/report/reason/spot deletes are accepted-ID scoped. Only dataset name `postflop` may receive version mutations. No schema, legacy, preflop, flop-base, account, ranked or removed hand-EV write belongs in delivery SQL.

The final footer retains complete touched-spot policy hashes and binds the collection, delivery source and row ledger identities. If its complete escaped statement exceeds the bound, conversion fails rather than truncating IDs. Formal SQL is deterministic: no wall-clock/random revision creation. An early JSON/CASE assertion permits only the exact predecessor or this delivery's final content hash. Immediate replay is idempotent; old A after B is rejected. A new A-prime revision/predecessor requires explicit new independent delivery review.

Temporary output files are exclusive. Completed SQL and a deterministic manifest are published only after expected hash/length/source/index/receipt rechecks. The manifest completion marker is last. Any failed preparation removes its own partial output. `--check-bundle` regenerates accepted-byte conversion and compares every byte, both EOFs, trailing content and the derived manifest. There is no execute/remote/deploy option.

## Restoration and historical fixtures

Only after the last destination passes does a second serial pass call the unchanged v1 restorer. Existing identical bytes are reused; conflicting bytes fail before ordinary first-pass writes. Recheck sources/children immediately before each restore. Concurrent hostile mutation or disk faults are not a filesystem transaction. Use a fresh isolated checkout and expose completion only after final verification.

The fixture-only Python restorer requires an explicit disposable-checkout flag and completely empty canonical local artifact directory. The separate historical accepted snapshot positive check requires its exact 95-file historical root and invokes that root's own verifier. It must not mix current imported modules with an arbitrary historical-root argument. Its exact archive/manifest/receipt hashes are pinned in the tests; the unchanged current v1 verifier must reject those historical source records. This is local regression evidence, not a permanent extra historical-source CI artifact.
