# ポストフロップAI推定：現行の対応範囲とローカル実行

更新: 2026-10-01。AI推定の実験機能であり、GTO・均衡解・利益の証明ではありません。初版の固定50%継続モデルや代表12ボード限定の画面仕様は現行仕様ではありません。

方針を作る・作り直すときのナレッジ（手順、指示文の要点、監査警告の読み方、過去の失敗）は [postflop-policy-knowledge.md](postflop-policy-knowledge.md) にまとめています。

## 正本・依存関係

- 局面: `scripts/postflop-ai/spots.mjs`。保存済みプリフロップJSONから席、到達レンジ、ポット、スタックを決めます。
- ボード・サイズ・シード: `scripts/data/postflop-ai-pilot.json`。
- フロップ: `scripts/postflop-ai/policy.mjs`、`tree.mjs`。ターン・リバー: 同ディレクトリの `later-policy.mjs`、`later-tree.mjs`。
- 保存候補: Git管理外の `.local/postflop-ai/{slug}-policy.json`、`{slug}-later-policy.json`。入力・方針ハッシュを検査して読み取ります。
- 画面: `src/estimated/postflop-compute.ts` と共有の `scripts/postflop-ai/views.mjs`。ブラウザーとローカル読み取りミドルウェアで同じ計算を使います。
- 防御計算: `scripts/postflop-ai/defence.mjs`。モデルと制限は [postflop-defence.md](postflop-defence.md) が正本です。

独立したRust Solverの [研究計画](../../../docs/postflop-solver-plan.md) とは別です。閲覧操作で候補の生成・公開やプリフロップJSON変更はしません。

## 対応経路

標準設定（6-maxキャッシュ、100BB、アンティなし）の48列挙局面のうち44局面が到達可能です。

| 経路 | 到達可能数 | 到達レンジ |
| --- | ---: | --- |
| オープン → 1人だけコール | 11 | RFI、保存コール頻度 |
| オープン → 3bet → オープナーがコール | 15 | 3bet、RFI × 3betへのコール |
| オープン → 3bet → 4bet → 3bettorがコール | 15 | RFI × 4bet、3bet × 4betへのコール |
| SBリンプ → BBチェック／BBアイソレート→SBコール／SB再レイズ→BBコール | 3 | 各経路の保存頻度の積 |

SBのオープンに対する保存レンジは3bet-or-foldのため、SBがフラットコールする4経路は到達不能です。マルチウェイ、5bet後、その他の未対応経路を別局面の方針で埋めません。44という数は経路の対応範囲であり、全候補が存在・最新・独立に監査済みという意味ではありません。実際の保存状態は局面一覧や管理画面で確認します。

## 画面・ボード・サイズ

対応プリフロップ経路を完了すると、同じワークスペースでフロップへ進めます。スート別モーダルは任意の異なる3枚、ランダムフロップ、代表12ボードのクイック選択を提供します。カードブロックは行動履歴内に並び、クリックで再選択できます。行動ブロックのクリックはその判断へ巻き戻します。

行動が完了すると次ストリートのカード選択が自動で開きます。ターン・リバーは使用済みカードを除外します。閉じたモーダルはカードブロックから再度開けます。リバーまでレンジ全体、ハンドクラス平均、到達可能な正確なスート組合せの頻度・説明を表示します。ハンドクラスEVをコンボ固有EVとして表示しません。

**代表12ボードは候補生成・監査・任意の事前計算EVの対象であり、実行時の制限ではありません。** 生成用8ボードと伏せた検証用4ボードを使います。任意ボードへの方針適用は全ボードでの品質検証を意味しません。

最後のプリフロップレイザーがOOPなら `oop_leads`、それ以外は `oop_checks`（レイザーなしのSBリンプ→BBチェックも `oop_leads`）。サイズは33%／75%／125%ポット、レイズは3倍、リバーは明示的なオールインも扱います。残り有効スタックの67%以上を入れるサイズはオールインに統合し、その後はカードを配るだけです。互換名 `btn_*` はIP、`bb_*` はOOPです。

ベット頻度とレイズ比率はAI方針に基づき、コール／フォールドは相手の到達レンジ、カード除去、エクイティ、レーキ後の必要勝率、実現率の仮定から計算します。ソルバーの均衡防御ではありません。

## EVと欠損

フロップ事前計算EVは入力・方針ハッシュと防御モデル版が一致する場合だけ利用します。非代表ボード、欠損・古いEV行はブラウザーのWeb Workerでオンデマンド計算します（サンプリングなしの厳密な期待値。両者が表示中の戦略に従う場合の値で、GTO EVではありません）。

方針自体の欠損・不正・古い入力は表示を停止します。ターン・リバー画面には保存済みlater方針が必要で、CLI比較用の参照方針を黙って代入しません。

## ローカル実行順

`apps/frontend` で保存状態を確認してから必要な生成だけ明示実行します。以下は手順であり、閲覧・ドキュメント更新時に自動実行するものではありません。

```sh
npm run postflop-ai:spots
npm run postflop-ai:generate -- --spot BTN_open_BB_call
npm run postflop-ai:generate-later -- --spot BTN_open_BB_call
npm run postflop-ai:simulate -- --spot BTN_open_BB_call
npm run postflop-ai:audit -- --spot BTN_open_BB_call
npm run postflop-ai:hand-ev -- --spot BTN_open_BB_call   # オフライン研究用のみ。プロダクトはポストフロップのEVを出さない（2026-10-01 決定）
```

`--spot` の既定は `BTN_open_BB_call`。既存候補は自動上書きしません。入力が変われば停止し、再生成には既存候補・レポートの退避と明示実行が必要です。モデル設定と出所は `generate.mjs` と候補metadataで確認します。

監査は合法アクション、頻度合計、カード重複、ハッシュ、固定シード再実行、チップ保存・レーキなどの整合性を検査します。未コール額は返却してからレーキを計算します。代表ボードの固定相手比較や信頼区間は実戦人口・全ボードを代表せず、監査合格は最適性の証明ではありません。公開は別途明示した判断・操作です。
