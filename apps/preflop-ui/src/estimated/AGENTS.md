Present the data positively as an AI-generated solution for beginner/intermediate players (not as "GTO未検証"); never claim GTO or solver output. ## Audit gate (2026-09-23)
`src/estimated/audit.js` checks range flow, auto-profit overfolding (open/3bet/4bet), strength order within hand families (A5x-over-A6x is an allowed wheel/blocker exception), suited-vs-offsuit, open position nesting and defense tightening vs earlier openers. Generators refuse to write `src/estimated` directly: `npm run build:estimates` regenerates into a staging dir and publishes only when the audit reports zero findings. `tests/estimated-audit.test.mjs` keeps persisted data at zero findings. `npm run audit:estimates` prints the report. SB uses dedicated 4bet-response profiles because its wider 3bet range overfolded to 4bets.

## Detailed reasons prototype (2026-09-23)
`scripts/reason-facts.mjs` computes per-hand facts (Monte Carlo equity vs the opener range and vs the range continuing after a 3bet, blocker share, call break-even, opener fold-to-3bet). AI-written per-hand reasoning lives in `scripts/reasons/<spot_id>.py` with placeholders; `scripts/reasons/render.py` fills every number from facts and saved frequencies, refuses to write when wording contradicts the mix, and emits `src/estimated/reasons/<spot_id>.json`. The UI lazy-loads that file (`detailed-reasons.js`, one chunk per spot) only when a hand's details open, falling back to the saved `reason`. Prototype covers BB_vs_BTN only. Sizes stay fixed by `configs/cash-6max-100bb.json`.

## Five-bet responses and reasons for every spot (2026-09-24)
User approved persisting the original opener's call/fold response to the 3bettor's 100BB 5bet all-in (15 spots, `five-bet-responses.json`). It is computed, not hand-authored: equity vs the saved shove range (3bet × all-in frequencies) against pot odds, seeded Monte Carlo, ±2pt linear mix band. `generate-five-bet-responses.mjs` runs last in `npm run build:estimates`, and the audit adds its range-flow and shover auto-profit checks. The UI lazy-loads it only on the all-in path and prefers it over local Codex generation, which stays as a fallback for spots without data. Multiway/squeeze ranges are left to the separate action-tree work to avoid duplicate datasets.
Detailed reasons now cover every spot: `reason-facts.mjs` computes type-specific facts for all 64 spots into `.local/reason-facts`, and `compose-reasons.mjs` writes `src/estimated/reasons/<spot_id>.json` (BB_vs_BTN stays hand-written). Reason files carry `fact_labels`, so the detail panel renders each spot type's own numbers.
Cross-model review tooling lives in `scripts/review/` (README explains the blind/critique modes, canaries and consensus rule). Reviewers must be a different vendor from the generating model.
